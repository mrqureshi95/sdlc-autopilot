# SDLC Autopilot 2.0.0

Provider-neutral guidance for proportional coding, read-only review and honest
local verification. The complete package is `skills/sdlc-autopilot/`; copying only
SKILL.md omits required runtime resources and the license.

## Changes

- Separate task type from risk; preserve existing user edits, accepted authority
  and scope without routine approval pauses or automatic cleanup.
- Replace heuristic readiness claims with scoped pass/fail/inconclusive/not-applicable
  observations, exact Git provenance, optional task-start snapshots and final-state
  stability checks. Recognize branch, worktree, untracked and index-masked edits.
- Add positive test evidence for Node, pytest, unittest, Jest/Vitest JSON and fresh
  JUnit reports. Existing tests can suffice; empty/skipped/opaque execution does not.
- Configure maintained secret scanning, checksum-pinned explicit scanner preparation,
  no implicit downloads, and bounded reviewed project commands.
- Replace generic security/deployment recipes with relevant trust-boundary and
  platform-specific review. External model review stays explicitly authorized.
- Repair locked evaluation fixtures and semantic controls; distinguish replay,
  structural tests and human judgments from live-agent effectiveness.
- Include a one-page HTML guide, audit records, host installation smoke tests,
  and an optional local [usefulness measurement protocol](../measuring-value.md).

## Breaking helper contracts

Exit 0 means applicable required checks were satisfied, 1 is an observed failure,
and 2 is missing required evidence. Standard behavior requires positive recognized
test execution; Full behavior also requires scoped configured security evidence.
Unsupported direct project evidence can still be reported separately. Automatic
inversion is unsupported and returns 2. Existing coverage files and assertion
counts are not accepted as proof. Read-only review does not execute project checks.

Review `.sdlc-checks.json` and wrappers before execution. Configure actual local
runners; do not relabel tests as lint to obtain a green result. Use absolute helper
paths from the installed package. Helpers require Python 3.10+, Git and POSIX
process handling; Node 22+ for the Node adapter. Project runners/tools are separate.

## Verification and limits

The final local audit exercised 55 Python regressions, three named Node checks,
twelve real runner controls, three official CLI installation layouts, eight
original-versus-revised helper cases, 35 fixture tests, five semantic before/after
controls, and 26 structural scenarios (ten with semantic oracles). The monorepo's
intentional broken source import is reported separately, not counted as passing.
Maintained secret scanning and a dependency-advisory check supplement these tests.
Exact current remote results are in
[GitHub Actions](https://github.com/mrqureshi95/sdlc-autopilot/actions/workflows/validate.yml).

This is evidence of specific package/helper behavior, not a cross-model pass rate
or a guarantee of correct or secure projects. Model adherence, assertion relevance,
native Windows helpers, application-specific security and hostile-code isolation
remain outside those claims. The skill collects no usage telemetry. The optional
study files are templates only; real usage and controlled comparison data have
not yet been gathered by this release.

## Install and update

```sh
npx skills add mrqureshi95/sdlc-autopilot --skill sdlc-autopilot -a codex
```

Select `claude-code` or `opencode` for those hosts. Inspect destination and installer
version; the CLI command installs project-locally unless global scope is selected.
For a reproducible source use the repository's `v2.0.0` tag. Preserve any customized
installed copy before replacing the complete folder, and confirm `metadata.version`
is `2.0.0`. Codex detects skill changes; use a new turn, restarting only if the
updated skill is not discovered. Package compatibility does not prove equal
behavior across models.
